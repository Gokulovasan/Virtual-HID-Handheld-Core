Project Description: OpenHID Handheld Framework (Virtual-HID-Handheld-Core)Virtual-HID-Handheld-Core is an industrial-grade, zero-hardware C99 input middleware layer designed to convert compact USB keyboards into virtual HID gamepads with mouse-pointer emulation. Developed specifically for low-power Linux single-board computers (such as Raspberry Pi) running emulation ecosystems (RetroArch, Batocera, Lakka), the software bridges hardware keypresses to native kernel input interfaces without requiring physical wiring modifications or custom microcontrollers.  Executive Summary & Problem StatementBuilding portable retro-gaming handhelds typically requires custom PCB fabrication, microcontroller wiring (e.g., Teensy, Raspberry Pi Pico), and dedicated analog joystick integration.  Virtual-HID-Handheld-Core eliminates physical hardware complexity by operating at the Linux kernel boundary. By utilizing /dev/input/event* (evdev) and /dev/uinput primitives, the engine captures low-level key matrix signals from standard compact USB keyboards and remaps them into a unified, virtual gamepad controller with dynamic mouse acceleration—achieving a fully functional handheld interface through software alone.  Core System FeaturesKernel-Level Input Interception (evdev): Uses POSIX file descriptors to read raw input_event structures directly from the secondary keyboard interface.  Exclusive Device Locking (EVIOCGRAB): Locks the targeted keyboard device at runtime to prevent keypress leakage into host terminal sessions or desktop environments.  Virtual Gamepad Emulation (uinput): Creates a virtual USB HID gamepad emitting Linux input signals (BTN_SOUTH, BTN_EAST, BTN_NORTH, BTN_WEST, BTN_TL, BTN_TR, BTN_START, BTN_SELECT) recognized out-of-the-box by game engines and emulators.  Relative Mouse Vector Engine: Maps a dedicated directional key cluster (I/J/K/L) to relative cursor coordinates (REL_X, REL_Y) for full menu navigation without a physical mouse.  Deterministic C99 Architecture: Written in strict C99 without dynamic memory allocation (malloc/free), guaranteeing zero runtime heap fragmentation and predictable $O(1)$ execution performance.
